# Follow-on eight My First Battle fronts

This finite lane publishes eight retained, unchanged English My First Battle
fronts and twenty-four display derivatives. All originals are 1375 × 1920 JPEGs;
derivatives use the accepted no-enlargement pipeline. Accepted internal catalogue
aliases are 5, 7, 11, 23, 26, 27, 29 and 31. These cards are unnumbered; species/Dex text
and internal aliases do not become printed collector numbers.

Separately viewed originals corrected earlier mistaken BASIC-stage and frame
observations. The append-only reconciliation and each original/raw metadata hash
remain pinned; historical holds stay identified as superseded observations.
Exact name, HP, stage/evolution, type, artist, ordered attack/cost/damage/effects
and deck silhouette are supported by actual pixels and independent source data.
Historical source-signature hashes use recursively sorted compact JSON with
literal Unicode and array order retained; current structured-body hashes remain
independently pinned.

The earlier fifteen must be live before freezing against fresh exact-eight
snapshots. Preserve both existing inactive, `under_review` provenance source
rows, old set artwork/links, canonical data and variants. Production inserts no
source and changes no existing source policy. Staging's two temporary source
fixtures and artwork metadata exist only within rollback rehearsals. Keep the
earlier fifteen outside this cohort. Exeggutor6 remains excluded because printed
HP 120 conflicts with two metadata sources reporting 90; ten source-choice
ambiguities also remain unresolved. Neither fixed batch is complete.

Owner-attested site permission, per-file attribution and image-specific rights
facts remain explicit. Independent vendor/copyright licence, physical edition or
finish verification and source-wide activation remain false. This workflow only
publishes the exact frozen artwork. It requires main SHA, dedicated confirmation
`PUBLISH ARTWORK MFB8 FRONTS`, production environment and shared deployment
concurrency, verifies all 32 image files before database/storage operations,
retains failure journals and prepares scoped rollback evidence. Root separately
verifies the configured API and four served image files for each card.
