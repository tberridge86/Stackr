## Protected production execution

The route directly reuses the accepted 48-front metadata guard/source resolver
and Stackr's existing immutable transfer/transaction publisher.
`publish.mjs --execute` requires the exact main SHA, a manual GitHub workflow,
both verified database projects and
`STACKR_ARTWORK_LATIOS_TRAINER_KIT_CONFIRMATION=PUBLISH ARTWORK LATIOS TRAINER KIT`.
Set `STACKR_ARTWORK_LATIOS_TRAINER_KIT_PACKAGES` to extracted packages and
`STACKR_ARTWORK_LATIOS_TRAINER_KIT_OUTPUT` to public receipts. The coordinator
owns the protected workflow and shared production concurrency.

The guard preserves all 32 printings, 32 normal variants, 64 names, two sets
and every scoped existing asset/link/source. It rejects drift or scope growth
before commit; an idempotent repetition creates nothing. Public receipts contain
hashes/counts, never full private metadata. Optional
`STACKR_ARTWORK_LATIOS_TRAINER_KIT_PRIVATE_OUTPUT` stays outside public receipts
and must remain unset in hosted production. Keep `before-query.sql` output private.

Rollback files are prepared but never executed automatically. They hide only
new asset UUIDs bound to this exact printing/hash/cohort, retaining immutable
objects, links, previous artwork and source policies. The coordinator must
verify configured production card/manifest responses and every served image
before closing eligible items. Local validation does not establish publication.
