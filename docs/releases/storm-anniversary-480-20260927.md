# Storm Emeralda and 30th anniversary metadata import

The production catalogue contains empty Storm Emeralda and anniversary set shells. This bounded release imports 480 reviewed physical-card printings: Japanese Storm Emeralda (113), English 30th Celebration (161), Japanese 30th Celebration (176), and a separate English Classic Collection (30). It preserves existing production set IDs and creates only the missing Classic set. Pocket is a separate product and release.

TCGdex supplies 450 records; Pokemon TCG API supplies the Classic Collection's 30 factual identities and printed numbers. Frozen raw payloads, source URLs, hashes, provider mappings and source attribution accompany every printing. TCGdex's existing MIT notice remains in THIRD_PARTY_NOTICES.md. Unknown provider rarities remain unknown; newly named rarities retain their provider labels. Visual inspection corrected TCGdex's swapped names/artists for Storm numbers 098 and 099 before any production import.

The same atomic release publishes 279 printing-front external image references under the existing approved official Japanese source: 113 Storm and 166 anniversary cards. All source files were fetched, hashed and fully decoded; they are rechecked before writes and after commit. Images remain on the official source, with no mirrors or derivatives. Source permission and owner-confirmation notes are checked without changing global rights. These references are not approved for recognition training. The combined LEGEND image is withheld from both halves; the landscape Greninja BREAK image is a visually verified single card.

Ten Japanese anniversary image gaps remain: 119, 121, 128, 129, 131, 151, 152, R, G and B. Six sampled English anniversary/Classic Scrydex image URLs all returned HTTP 403; no English artwork is published by this release. The separate Pocket release completed 131 assets and 524 public files in run 36328603018.

Classic contains three different cards numbered 106 and two numbered 11. The additive canonical-key contract accepts an optional `:printing:<actual printing UUID>` suffix while preserving every existing key. Printed numbers and finish taxonomy remain unchanged; the existing unique printing/variant and composite identity constraints continue to apply. The 30 Classic records use this explicit identity. TCGdex validation quarantines the Classic list-position feed so a later generic import cannot recreate those positions as printed numbers. Other anniversary records remain importable. No existing key is rewritten.

The first protected rehearsal (36329827434) detected staging's additional natural-identity unique index and rolled back before production. The unapplied migration now adds an explicit printing discriminator: ordinary printings retain their existing uniqueness protection, while reviewed reprints are unique by printed number plus provider printing identity. The PostgreSQL test covers environments both with and without the older index and retains the real composite foreign key. This does not reconcile other historical migration drift or apply the pending older natural-identity repair in production; a future broad migration rollout must account for printing discriminators.

Reviewed exceptions include separate paired Stadium numbers 071–076, separate LEGEND halves, the existing Pikachu sequence (not another duplicate subset), RGB Mew identifiers, the eight visually confirmed Japanese energy codes, and the official Mega Gardevoir name for M6a-156. Japanese official gallery omissions do not shrink the source checklist.

The exact frozen cohort uses separate staging and production bindings. Staging contains 242 older Japanese printings and incorrect set totals; the complete rehearsal preserves their identities and rolls back every change. Production begins with zero printings in the three existing shells. Both environments rehearse the one pinned migration plus every metadata, asset and membership write in a serializable transaction before production commits. The migration is recorded with its exact statement in the migration ledger. The lane does not apply other pending migrations. Post-commit verification requires all 480 selected variants in the published catalogue view and all 279 references in the public asset manifest.

Validation includes frozen-source and identity tests, repeated-number and LEGEND/energy checks, release guards, failure rollback, and an isolated PostgreSQL migration test proving old keys remain valid and mismatched UUID suffixes fail. Full CI and protected production execution remain required. External Stackr HTTP route delivery and installed-device rendering are separate from catalogue and source-image verification.

Rollback must be a separately reviewed forward change scoped to this cohort's version membership and newly inserted identities. Preserve ownership data and any subsequently referenced records. Do not restore the old key constraint while printing-scoped keys exist. Existing artwork releases remain outside this scope.
