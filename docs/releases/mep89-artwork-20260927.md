# MEP 89 artwork publication — 27 September 2026

The existing English MEP catalogue has 89 cards without published artwork. The owner confirmed Scrydex storage, resizing and Stackr display for the reviewed batch on 27 September. This release adds printing-front images to those existing cards, with null variant links and recognition disabled. The Museum Pikachu retains its existing unnumbered identity and the provenance records its jumbo format.

The frozen cohort contains 88 numbered promos and one Museum card. All originals were acquired and decoded before permission was requested. The release fetches only these 89 exact URLs and requires the reviewed SHA-256, byte length, PNG format and full decoded dimensions. It produces the established grid, search and detail derivatives: 356 stored files total.

A separate, inactive `scrydex` provenance row remains under review globally. Approval is carried on these 89 exact assets with the owner attestation and cohort hashes. No general Scrydex acquisition capability is enabled. An unexpected existing source row or conflicting artwork stops the release rather than changing it.

The existing protected production workflow adds the `mep89_artwork` scope, under the same deployment lock. Exact-main validation, forbidden unrelated flags and receipt secret scanning remain required. Both staging and production metadata rehearsals insert the complete source/asset/link cohort and roll back before the first storage upload. Staging retains no publication. Production uses a serializable additive transaction after all bytes are verified. Existing exact storage objects are hash/decode checked and reused; uploads never overwrite. The final public manifest and all 356 anonymous image responses must pass before delivery is reported.

Local validation: 82 tests across the three bounded publishers pass. All 89 local originals and 267 generated derivatives fully decode (356 unique keys; 81,458,546 bytes); a corrupted original is rejected. CI and protected release results are pending. This is not phone-rendering evidence.

Rollback/recovery: before commit, metadata failures roll back; newly uploaded objects may remain unlinked and are recorded in the receipt. Do not delete shared content-addressed objects. If commit acknowledgement is uncertain, reconcile the frozen asset IDs before any rollback. After commit, an image-verification failure is reported as published but unverified, never as a rolled-back release. Any withdrawal must be bounded to receipt asset/link IDs and must first check for later consumers; no catalogue, ownership or source-wide cleanup is included.

Storm Emeralda, the 30th anniversary groups and Pocket remain outside this 89-image release. No new-set metadata is imported by this publisher.
