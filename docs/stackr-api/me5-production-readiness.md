## Provider and image legal-use status

Status: **under_review**.

Evidence reviewed:

- [Pokemon TCG API documentation](https://docs.pokemontcg.io/)
- [Pokemon TCG API rate-limit documentation](https://docs.pokemontcg.io/getting-started/rate-limits)
- [PokemonTCG data repository](https://github.com/PokemonTCG/pokemon-tcg-data)
- [GitHub repository licence endpoint](https://api.github.com/repos/PokemonTCG/pokemon-tcg-data/license)

The public API documentation describes access and rate limits but does not state a catalogue or image reuse licence. The repository reports no SPDX licence and its licence endpoint returns `404`. This is evidence of missing approval, not proof that use is forbidden.

The production adapter therefore defaults catalogue records and images to `under_review`, disables automated refresh, quarantines non-approved canonical records, and returns no asset records unless image permission is explicitly approved. Raw provider payloads remain private.

## Identity and provenance

Canonical card identity remains:

`game + language + canonical set UUID + collector number + variant code`

Card names are never used as unique identities. The adapter preserves collector-number text, parses sortable components, leaves unknown finishes unset and does not claim that provider card IDs are artwork identities.

Every provider set response, card-page envelope and card record carries:

- provider and provider record ID;
- endpoint;
- payload checksum generated by the ingestion pipeline;
- raw payload;
- retrieval time;
- provider update time;
- licence status;
- HTTP response metadata;
- import-run ID.

The new unique index scopes raw identities by import run, retaining complete history while preventing duplicate processing inside one run.

## Rollback and activation

The migration rollback script is guarded: it aborts instead of deleting raw provenance or referenced rarity rows.

Canonical import rollback must be generated from the import-run and merge-decision audit rows. Existing canonical rows may have been updated, so deleting every touched entity is unsafe. Imported identities should be soft-deprecated or restored from recorded prior values.

Catalogue activation controls are not ready in this branch. The database has draft/published/rolled-back status values, but there is no reviewed atomic activation command that validates completeness, records the sequence range and restores the prior version. This remains a release blocker.
